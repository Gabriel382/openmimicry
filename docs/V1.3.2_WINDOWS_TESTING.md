# OpenMimicry v1.3.2 — Windows voice lifecycle test

This checklist targets the speech cutoff, repeated TTS, duplicate text,
scrolling, and desktop shutdown behavior reported against v1.3.1.

## 1. Clean start

Use exactly one backend. In the first PowerShell window:

```powershell
cd C:\Users\henri\Documents\git\personal\openmimicry
powershell -ExecutionPolicy Bypass -File .\scripts\win\start-openrouter-voice.ps1
```

Wait for `RealtimeSTT/RealtimeTTS imports OK` and `Application startup
complete`. In a second window:

```powershell
cd C:\Users\henri\Documents\git\personal\openmimicry
.\scripts\win\desktop.bat
```

The backend should settle at three WebSocket clients: avatar, controls, and
composer. React may briefly connect/close during development startup, but the
total must not remain at six.

## 2. Set the phrase pause

1. Click the toolbar gear to open the localhost dashboard.
2. In Voice, set **End-of-speech pause** to `1.3` seconds and save.
3. Confirm the page reports the saved value.
4. Confirm `config/user.yaml` contains:

```yaml
voice:
  stt:
    post_speech_silence_duration: 1.3
```

The control accepts `0.2`–`3.0`. Start near `1.0`; use `1.3`–`1.6` if you
pause often, or `0.5`–`0.8` if response speed matters more than long pauses.

## 3. Push-to-talk endpoint test

1. Hold the toolbar microphone or `Ctrl+Space`.
2. Say: “Mimi, explain the first point …” Pause for about 0.7 seconds, then
   continue: “… and then explain the second point.”
3. Release only after the last word.
4. The control must show `Listening`, then `Transcribing`, then the recognized
   phrase/no-speech result.
5. Conversation history must contain one `You · voice` turn with both clauses.

PTT does not require `Mimi`; the name is only required by Wake listen.

## 4. Repeated audio and synchronized text

Keep Agent voice on and send five short questions, mixing typed input and PTT.
For every turn:

- the avatar enters thinking, then speaking;
- the new text replaces the prior reply and appears once as audio begins;
- Windows plays the complete response, including replies 2–5;
- the avatar exits speaking after playback;
- dashboard history contains one user turn and one assistant turn.

The backend should log an audio-stream start/stop for every audible reply, not
only the first one.

## 5. Reply scrolling

Ask for a reply long enough to exceed the bubble. Click the toolbar button
with the document/lines icon, next to the lock. Its pressed state enables reply
interaction. Verify mouse wheel, scrollbar drag, Page Up/Page Down, and arrow
keys work after focusing the bubble. Click the button again to restore desktop
click-through behavior. `Ctrl+Shift+M` remains the keyboard alternative.

## 6. Desktop error checks

Because desktop WebSockets now connect directly to port 8000, Vite should not
print `ws proxy socket error: ECONNABORTED` during ordinary operation or exit.

Exit through the toolbar X. v1.3.2 explicitly closes all webview windows before
terminating Tauri. This mitigates `Failed to unregister class
Chrome_WidgetWin_0. Error = 1412`. If that line still occurs only once after a
successful exit, capture the Tauri CLI version, Microsoft Edge WebView2 runtime
version, and whether the process actually remained alive; the message can be
an upstream WebView2 teardown warning rather than an OpenMimicry runtime crash.

## 7. Pass criteria

- Paused phrases are complete at the selected endpoint value.
- Replies 1–5 all speak and display once.
- Text appears when playback begins.
- Long replies scroll while interaction is enabled.
- Backend settles at three desktop WebSockets.
- No Vite `/ws` proxy `ECONNABORTED` error.
- Toolbar exit leaves no `openmimicry-desktop.exe` process.
