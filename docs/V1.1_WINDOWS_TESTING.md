# OpenMimicry v1.1.0 — Windows desktop testing

## 1. Safe Sprite2D test

From the repository root:

```powershell
corepack enable
corepack prepare pnpm@11.0.0 --activate
.\scripts\win\install.bat basic
```

Terminal 1:

```powershell
$env:OPENMIMICRY_PROFILE = "basic"
.\scripts\win\backend.bat
```

Terminal 2:

```powershell
.\scripts\win\desktop.bat
```

The desktop shell opens three coordinated windows:

- the transparent, click-through avatar;
- an interactive drag/message strip immediately below it;
- the full panel.

Drag only the labelled control strip. The avatar follows it and the position is
saved. `Ctrl+Shift+O` shows or hides the panel. The avatar and its control strip
remain always on top.

## 2. Configure window appearance

Edit `config/theme.yml` and restart the backend and desktop shell. It controls:

- avatar, controls, and panel window dimensions;
- always-on-top behavior;
- avatar scale and width;
- panel, bubble, input, accent, and control-strip colors;
- visibility of the drag handle and bottom message field;
- completed-reply display time.

The bubble duration is:

```text
min(max_ms, base_ms + reply_character_count * ms_per_character)
```

The default is a 2.5-second pad plus 55 ms per character, capped at 30 seconds.

## 3. OpenRouter plus free local voice

Voice input uses local RealtimeSTT/Whisper. Voice output uses the operating
system's local speech engine. Neither requires a paid speech API. OpenRouter is
the only network provider in this profile.

Install the optional dependencies:

```powershell
.\scripts\win\install.bat openrouter-voice
Copy-Item .env.example .env
notepad .env
```

Set this line in `.env`:

```dotenv
OPENROUTER_API_KEY=your_real_key_here
```

Do not commit `.env`; it is ignored by Git. Start the backend:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\win\start-openrouter-voice.ps1
```

Then, in another terminal:

```powershell
.\scripts\win\desktop.bat
```

The profile defaults to `openrouter/openai/gpt-4o-mini`. To select a different
model without editing the tracked profile, add this to `.env`:

```dotenv
OPENMIMICRY__LLM__MODEL=openrouter/provider/model-name
```

For French speech recognition, add:

```dotenv
OPENMIMICRY__VOICE__STT__LANGUAGE=fr
```

The first local STT launch may download its Whisper model and take longer.

### Voice controls

- **Agent voice** controls whether future LLM replies are sent to TTS. Turning
  it off also interrupts the current utterance.
- **Live wake** opens local microphone listening and uses the wake names in the
  profile (`Mimi`, `Hey Mimi`). Final transcripts are automatically submitted
  as chat turns.
- **Ctrl+Space** is push-to-talk. Press to start dictation and release to submit
  the final transcript.

The panel reports the active STT/TTS adapter. If it says `(mock)`, button state
changes are test-only and no microphone or speaker audio is expected.

## 4. Structured emotion and action output

`config/personality.yml` defines the allow-listed output vocabulary. The LLM is
asked for:

```json
{
  "reply": "Visible and spoken answer",
  "emotion": "happy",
  "action": "wave",
  "intensity": 0.8
}
```

Only allow-listed emotions/actions reach the avatar. Invalid values fall back
to `neutral` and `idle`; malformed or plain-text model output is still shown as
a normal reply. Sprite2D maps cues to its available frame states while 3D and
external runtimes retain the gesture/action field.

## 5. Task cards

No task should be running while the companion is idle. The backend and desktop
processes are services and are not task cards. A task card is created only when
the message matches an explicit delegation phrase, including:

```text
Ask Claude to summarise the README
Use the MCP agent to inspect the repository
Run local shell to list files
```

The `basic` and `openrouter-voice` profiles route these to the mock task runtime,
so the UI can be tested without executing commands. Real Claude Code, MCP, or
allow-listed shell execution requires a separately configured task profile.
