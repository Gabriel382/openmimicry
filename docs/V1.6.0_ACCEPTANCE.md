# OpenMimicry v1.6.0 acceptance guide

Use this checklist on the exact source/archive and dependency resolution being
reviewed. Record OS, Python/Node/Rust versions, hardware, audio devices,
profile, and commit hash with the results.

## Automated release gates

```bash
python -m pytest
python -m ruff check .
python -m ruff format --check .
python -m pyright
python scripts/check_imports.py
node --check apps/backend/src/openmimicry_backend/static/dashboard.js
pnpm install --frozen-lockfile
pnpm test
pnpm typecheck
pnpm build
pnpm audit --prod
python scripts/license_audit.py --profile commercial --strict
```

Validate every checked-in profile and the example character pack. Rust/Tauri
requires a toolchain-equipped host:

```bash
cd apps/desktop/src-tauri
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
```

## Interaction scenarios

- Submit two typed turns while TTS is enabled; both user turns enter history
  immediately and both replies reach a terminal speech event.
- Repeat with PTT twice and wake-name mode twice.
- Interrupt one reply, then verify the next reply speaks and stale events do
  not replace listening/thinking.
- Verify each presentation mode and force a TTS failure.
- Confirm a bubble remains for its reading timer and, when applicable, until
  the matching audio finishes.
- Verify the configured `ms_per_character`, minimum, maximum, and readiness
  timeout boundaries.

## Provider and personality scenarios

- OpenRouter: discover models, select one, set a session-only token, converse,
  restart, and confirm the token was not persisted.
- Ollama: discover loopback models and switch between two installed models.
  Confirm a non-loopback discovery URL is rejected.
- Save a personality prompt and verify it affects prose without expanding the
  allowed emotion/action list.
- Inspect history/logs and confirm the exact provider/model are observable.

## Memory scenarios

- With memory disabled, verify zero recall and zero retention.
- Enable local deterministic memory, state an explicit preference, finish the
  reply, then verify one inspectable record.
- Repeat the same fact and verify exact deduplication.
- Edit, export, delete, and confirmed-clear local records.
- Set an expired retention horizon and verify old local records are removed.
- Force recall timeout/provider failure; the typed reply must still complete.
- If LLM extraction is enabled, select a backend independently and verify
  invalid/non-JSON output stores nothing.
- If Hindsight is tested, record its version and test retain/recall against a
  disposable bank; administer/delete that bank through Hindsight.

## Character scenarios

- Download the v1.6 template and import it unchanged.
- Use the simple creator with idle and speaking images.
- Import a valid custom ZIP and activate it.
- Verify traversal, absolute path, symlink, oversized, duplicate-manifest,
  invalid-signature, and existing-ID archives are rejected without partial
  installation.
- In the commercial profile, verify a denied/unknown pack license is rejected.

## Voice scenarios per OS/device

- System TTS: speak three replies, interrupt one, then speak again.
- STT: PTT two turns and wake two turns; record transcript accuracy and
  endpointing behavior.
- Chatterbox (if claimed): prewarm, speak three replies with one worker,
  terminate the worker, and confirm the next turn creates a replacement.
- ElevenLabs (if claimed): use a disposable session token, speak two replies,
  revoke the token, and verify text fallback.
- Confirm clone upload refuses missing consent, invalid signatures, and files
  over 20 MiB.

## Privacy, license, and rollback

- Confirm diagnostics contain no API token or raw reference audio.
- Confirm raw microphone audio never enters memory/export.
- Run the license audit in a clean environment and retain the report.
- Confirm commercial artifacts contain no Piper/Chatterbox packages or
  unreviewed character/model assets.
- Start the untouched v1.5.1 rollback copy/profile and document the rollback
  time. Schema migration must not have rewritten the old source config.

An unavailable hardware/cloud/Rust gate is not a pass. Mark it **not run** with
the reason in release notes and complete it before claiming that platform or
provider as release-verified.
