# OpenMimicry v1.6.2 Chatterbox verification

## Windows acceptance path

From the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\win\start-openrouter-chatterbox.ps1
```

The first run must:

1. load `.env` without printing its secrets;
2. install or verify the `openrouter-chatterbox` profile;
3. print a JSON runtime report with `passed: true`;
4. report `cuda_available: true` on supported NVIDIA systems;
5. download/prewarm Chatterbox once and emit a worker `ready` object;
6. start the backend with the Chatterbox profile and a 180-second deadline.

After uploading a consented WAV/MP3 in the dashboard, restart with the same
launcher. Send at least three text turns. Each turn must show an LLM reply,
produce cloned speech, reach a terminal TTS event, and leave the next turn
usable. No site-packages file may be edited.

## Runtime probes

```powershell
.\.venv\Scripts\python.exe scripts\install_chatterbox_runtime.py `
  --python .\.venv\Scripts\python.exe --check-only

.\.venv\Scripts\python.exe -u -m `
  openmimicry.voice.workers.chatterbox_job --preflight --device auto
```

Expected worker fields include `device`, `torch_version`, `torch_cuda`,
`numpy_version`, and `numpy2_compat`.

## Failure behavior

- Missing reference or consent: text remains available and the error identifies
  the missing requirement.
- CPU Torch on an NVIDIA host: the launcher repairs it before backend startup.
- Unsupported GPU/Torch combination: installation stops with an actionable
  message rather than falling back silently.
- Model download/load failure: preflight fails before the backend is enabled.
- Worker crash or cancelled startup: the process is discarded; health checks
  do not start a replacement.
