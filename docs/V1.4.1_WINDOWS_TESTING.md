# OpenMimicry v1.4.1 — Windows repeat-turn test

This patch specifically verifies the failure reported in v1.4.0: one spoken
reply worked, then TTS, typed chat, and continuous STT stopped progressing.

## Start cleanly

Close old OpenMimicry terminals and processes. From the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\win\start-openrouter-voice.ps1
```

In a second PowerShell window:

```powershell
.\scripts\win\desktop.bat
```

Open the gear/settings page or visit `http://127.0.0.1:8000/dashboard`.

## Required repeat-turn matrix

Run these in order without restarting the backend:

1. Send `text one`, then `text two`, then `text three`. Each user turn must
   appear immediately. Each answer must appear and speak.
2. Hold PTT, say `What is your name?`, and release. Repeat with two different
   questions. All three recognized turns and answers must appear; all three
   answers must speak.
3. Enable continuous listening. Speak three separate questions, waiting for
   each spoken answer to finish before the next. The listener must restore
   after every answer and accept all three turns.
4. While an answer is speaking, press PTT. The answer may be interrupted, but
   the new PTT turn must transcribe and the next answer must still speak.
5. Close and reopen the dashboard while a reply is active. The backend must
   log a normal socket drop/reconnect, not an ASGI traceback.

Expected lifecycle log lines are numbered and paired:

```text
Turn 0001 queued / started / completed
TTS turn 1 queued / audio started / audio stopped / completed
STT session paused / started
```

`RealtimeSTT shutting down` is expected only for a real recorder replacement
(for example a model change) or application exit—not between ordinary
continuous-listening turns.

## Send a useful diagnostic bundle

In the dashboard, click **Download bundle** under **Diagnostics**. If the
dashboard is inaccessible, run:

```powershell
.\scripts\win\collect-diagnostics.bat
```

The versioned ZIP is written under `diagnostics\`. It contains rotating
lifecycle logs, voice-package versions, and sanitized runtime settings. It
does not include `.env` or API-key values. Review paths and transcripts before
sharing it.

When reporting a remaining issue, include:

- the diagnostic ZIP;
- which matrix step failed;
- whether the first answer finished audibly or was interrupted;
- the approximate time shown on screen when it failed.
