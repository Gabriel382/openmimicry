# OpenMimicry v1.3.1 — Windows voice regression test

This patch addresses the self-hearing/cancellation failure observed with
RealtimeSTT, Windows system TTS, and an OpenRouter LLM.

## Clean start

Run exactly one backend. In the first PowerShell window:

```powershell
cd C:\Users\henri\Documents\git\personal\openmimicry
powershell -ExecutionPolicy Bypass -File .\scripts\win\start-openrouter-voice.ps1
```

The launcher must print `RealtimeSTT/RealtimeTTS imports OK` and then
`Application startup complete`. If port 8000 already has a listener, v1.3.1
stops with the owning process ID; close the old backend window and retry once.

In a second PowerShell window:

```powershell
cd C:\Users\henri\Documents\git\personal\openmimicry
.\scripts\win\desktop.bat
```

The first STT use can download and warm up Whisper/Silero resources. Complete
any one-time trust prompt in the backend terminal before judging latency.

## Expected push-to-talk sequence

1. Hold the microphone button or `Ctrl+Space`: it pulses in the `listening`
   state.
2. Speak a complete question. PTT never requires the name `Mimi`.
3. Release: the button enters `transcribing`; the recording is not discarded.
4. The dashboard Voice card shows either the recognized text or an explicit
   no-speech result.
5. The recognized user turn appears in Conversation with the label `You ·
   voice`, followed by the assistant turn.
6. The avatar transitions `listening` → `thinking` → `speaking` → its final
   emotion/action or `idle`.

Typed turns appear as `You · text`. Conversation history keeps the latest 100
turns in backend process memory and therefore resets when the backend restarts.

## Expected wake-listen sequence

Wake listen is the hands-free, name-gated mode. Enable the waves button, then
say, for example:

```text
Mimi, explain why the sky is blue.
```

Speech that does not begin with the configured dashboard wake name is ignored.
After the avatar finishes speaking, the passive listener resumes automatically.

## Speaker-feedback safety

`voice.modes.barge_in_enabled` is `false` by default. Passive STT pauses while
TTS plays so laptop speakers cannot trigger VAD, cancel the TTS task, feed an
avatar reply back into the LLM, or grow the RealtimeSTT audio queue.

PTT still interrupts TTS immediately. Advanced users with headphones or
reliable acoustic echo cancellation may opt in through a config overlay:

```yaml
voice:
  modes:
    barge_in_enabled: true
```

## Regression checklist

- A new reply replaces old/incomplete bubble text rather than appending to it.
- Agent voice does not disconnect a desktop WebSocket.
- After TTS, the avatar does not remain on the `speaking/000.png` frame.
- PTT shows listening, then transcribing, then recognized/no-speech feedback.
- The dashboard history contains both typed and recognized voice input.
- Wake listen ignores unnamed background speech and resumes after TTS.
- The backend log has no uncaught `asyncio.exceptions.CancelledError` from
  `routes/chat.py`.
- Starting a second backend reports the port conflict before Uvicorn starts.
