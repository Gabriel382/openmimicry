# OpenMimicry v1.5.1 — Windows voice acceptance

This matrix is the release gate for the isolated Faster-Whisper/Piper runtime.
It specifically covers repeat turns, hung-process recovery, UI state priority,
and independence between OpenRouter text and audio.

## Clean installation

Close older backend and desktop processes. From the repository root:

```powershell
.\scripts\win\install.bat openrouter-voice
powershell -ExecutionPolicy Bypass -File .\scripts\win\start-openrouter-voice.ps1
```

The first launch downloads `en_US-lessac-medium` and `medium.en`, synthesizes
three separate WAVs, plays the last one, transcribes one sample, and records a
v1.5.1 pass marker. It must finish with JSON containing `"passed": true`.

If CTranslate2 detects an NVIDIA GPU but its CUDA libraries are incomplete,
`device: auto` retries with CPU/INT8. This is a passing portable configuration;
the JSON contains `"device": "cpu"` and a `fallback_reason`. Selecting
`device: cuda` explicitly remains strict and requires a complete CUDA runtime.

The Hugging Face symlink warning on Windows is informational. It means the
model cache may consume more disk space; it does not invalidate the preflight.

To repeat the hardware test:

```powershell
$env:OPENMIMICRY_VOICE_PREFLIGHT = "force"
powershell -ExecutionPolicy Bypass -File .\scripts\win\start-openrouter-voice.ps1
```

Start the desktop in a second terminal:

```powershell
.\scripts\win\desktop.bat
```

## Typed input and TTS

1. Submit ten numbered typed questions.
2. Each user message must appear immediately.
3. Each OpenRouter reply must appear before or independently of audio.
4. All ten replies must speak. Each uses a new worker PID/job.
5. A TTS failure must never remove the reply, disable text input, or prevent
   question 10 from reaching OpenRouter.

Expected logs repeat for every turn:

```text
Turn 0002 completed: ... reply_chars=...
isolated Piper playback started: duration=...
```

The legacy lines `loaded engine system`, `stream start`, and `Immediate stop
requested` must not appear.

## Push-to-talk

1. Hold the microphone button, speak a complete sentence, and release.
2. Confirm `listening → transcribing → thinking` and one history entry.
3. Repeat ten times without restarting or toggling voice.
4. Verify every release produces either one accepted transcript or an explicit
   no-speech result. No turn may remain in `transcribing` indefinitely.
5. Begin PTT while a reply is speaking. Playback must stop promptly, listening
   must remain visible, and the new transcript must be submitted.

The STT worker PID should remain stable across normal turns, demonstrating that
the stronger model is preloaded. If the worker crashes, the following voice
action may create a new PID but the backend must remain running.

## Wake listening

1. Enable wake listening once.
2. Say `Mimi, what is your name?` and wait for the configured silence interval.
3. Confirm the transcript and LLM submission occur without disabling wake.
4. Repeat with ten distinct name-prefixed questions.
5. Say one question without the name. It must appear as heard/not submitted and
   must not enter successful conversation memory.

Raise **End-of-speech pause** if normal clause pauses divide an utterance. The
new value applies when the isolated listener is restarted.

## State and interruption

- Thinking appears for both voice and typed LLM requests.
- Speaking starts only with actual audio playback.
- Pressing PTT while speaking changes to listening and stays there.
- A stopped playback job cannot later replace listening with speaking.
- Completing or failing TTS always restores passive listening when it was on.

## Diagnostics and exit criteria

Download **Diagnostics → Download bundle** after the matrix. The release passes
only when all 30 sequential turns complete, no backend restart occurs, no UI
state exceeds its deadline, and OpenRouter text remains usable throughout.

The bundle may contain transcripts and local paths; review it before sharing.
