# OpenMimicry v1.2.2 — Windows avatar and voice testing

## 1. Install the OpenRouter/local-voice profile

Run from the repository root in PowerShell:

```powershell
.\scripts\win\install.bat openrouter-voice
Copy-Item .env.example .env -ErrorAction SilentlyContinue
notepad .env
```

Set the key in `.env`:

```dotenv
OPENROUTER_API_KEY=your_real_key_here
```

The key stays in `.env`, which Git ignores. Start the backend with the guarded
launcher:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\win\start-openrouter-voice.ps1
```

The launcher checks the exact `.venv\Scripts\python.exe` used by the backend.
It verifies `AudioToTextRecorder`, `TextToAudioStream`, and `SystemEngine`. If
an import fails, it installs the RealtimeSTT `faster-whisper` extra and the
RealtimeTTS `system` engine into that environment, then checks again before
starting FastAPI. On Python 3.13 or newer, the profile also installs
`audioop-lts`, which supplies the audio compatibility module required by
RealtimeTTS/pydub. Complete Python diagnostics are preserved if repair fails.
The portable default uses faster-whisper on CPU with int8 compute, so CUDA is
not required for the first test.

Start the desktop from a second PowerShell window:

```powershell
.\scripts\win\desktop.bat
```

## 2. The top toolbar

The native settings panel no longer opens. The visible desktop companion has a
toolbar docked above the avatar:

| Control | Behavior |
| --- | --- |
| Grip | Drag the avatar and toolbar together. |
| Open/closed lock | Lock or unlock the saved position. |
| Microphone | Hold while speaking; release to transcribe and send. |
| Listening waves | Toggle Auto listen. |
| Speaker | Toggle whether assistant replies are spoken. |
| Gear | Open `http://127.0.0.1:8000/dashboard` in the default browser. |
| X | Stop and exit the desktop process. |

The transparent avatar and interactive toolbar remain two native windows
internally because Tauri/Windows click-through applies to an entire window.
They are docked, move together, stay always-on-top, and appear as one unit.

## 3. Push-to-talk versus Auto listen

### Push-to-talk

Hold either the toolbar microphone or `Ctrl+Space`, speak, then release. The
microphone is active only for that interval. This is predictable and uses the
least microphone time.

### Auto listen

Enable the listening-waves button. RealtimeSTT waits for ordinary speech using
voice activity detection. Start talking naturally; no wake word is required.
Each final utterance is submitted as a chat turn.

If Auto listen is on when PTT starts, OpenMimicry pauses Auto listen, completes
the PTT turn, and restores Auto listen afterward. This prevents two readers
from racing for the same microphone stream.

### What “wake” meant in v1.1

Wake mode listened for a configured phrase such as “Mimi” or “Hey Mimi” before
transcribing. It remains available as the advanced `live_wake` configuration
field for compatibility, but it is not shown as the normal desktop option.
Auto listen is the hands-free mode requested for v1.2.

## 4. Confirm real audio is active

Open the dashboard with the gear button. Under Voice, confirm the adapter line
shows:

```text
Input: realtimestt (microphone) · Output: realtimetts (audio)
```

If a dependency is missing, the dashboard and toolbar show the exact repair
command:

```powershell
.\scripts\win\install.bat openrouter-voice
```

Run the dependency imports directly when diagnosing:

```powershell
.\.venv\Scripts\python.exe -c "from RealtimeSTT import AudioToTextRecorder; from RealtimeTTS import SystemEngine, TextToAudioStream; print('voice imports OK')"
```

If a Python 3.13+ environment was created by an older OpenMimicry installer,
repair it once with:

```powershell
.\.venv\Scripts\python.exe -m pip install "audioop-lts>=0.2.2"
```

The first STT run may download a Whisper model. Windows may also request
microphone permission. Keep the backend terminal visible for device errors.

## 5. Browser dashboard and tasks

The backend serves the control board at:

```text
http://127.0.0.1:8000/dashboard
```

It contains chat, voice status, pack/runtime settings, adapter health, and the
task board. No task is expected while idle. Task rows appear only after an
explicit delegation message, such as `ask the MCP agent to ...` or
`run local shell to ...`. The default profiles use mock tasks for safety.

## 6. Appearance

Edit `config/theme.yml` and restart. It controls avatar/toolbar sizes, colors,
gap, visibility, scale, and reply reading time. The toolbar is docked above the
avatar in v1.2. Reply duration remains:

```text
min(max_ms, base_ms + characters * ms_per_character)
```
